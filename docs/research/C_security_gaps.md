## 3. Agent / non-human identity problem
- NHIs outnumber humans reportedly 82:1 (one study) up to 100-500:1 in some sectors; NHI volume +44% H1 2024->H1 2025; NHI governance at only 21% adoption (survey). [secondary: unite.ai, Kiteworks; UNVERIFIED]. https://www.unite.ai/agentic-ai-turns-nhi-sprawl-into-an-ungovernable-attack-surface/ ; https://www.kiteworks.com/cybersecurity-risk-management/non-human-identity-governance-ai-security/
- Mandiant M-Trends 2026 (via secondary source): machine identities a primary attack vector; harvesting long-lived OAuth tokens and hard-coded keys. [UNVERIFIED, verify in M-Trends]
- CSA whitepaper on NHI and agentic AI governance (May 2026): https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/05/CSA_whitepaper_nonhuman_identity_agentic_ai_governance_v1-csa-styled.pdf
- MCP auth: spec (June 2025) forbids token passthrough, requires audience binding and per-client consent for proxies (confused deputy). Reality: only ~8.5% of public MCP servers use OAuth, ~25% no auth, >50% static keys [UNVERIFIED, from SSOJet/WorkOS-style secondary]. Spec: https://modelcontextprotocol.io/specification/latest/basic/security_best_practices ; https://workos.com/blog/mcp-authorization-failures
- Human-in-the-loop fatigue: Anthropic says users approve ~93% of Claude Code permission prompts (later reported 97%); in its test humans caught 13.6% of disguised dangerous commands vs 89% for automated classifier; auto mode now default. Implication: plain "click approve" is weak; approval must be structured, rare, high-stakes, and cryptographically bound to the exact action. https://anthropic.com/engineering/claude-code-auto-mode ; https://devops.com/anthropic-makes-claude-codes-auto-mode-the-default-betting-automation-beats-manual-review/ (stats via secondary reports - verify in primary).

## 4. Single point of compromise (admin / IdP / key)
- Storm-0558 (2023): stolen MSA consumer signing key forged tokens for 22 orgs (incl. Commerce Sec. Raimondo). CSRB: Microsoft still did not know how key was stolen; Microsoft's crash-dump explanation unsupported; "preventable"; security culture "inadequate". Gap = one extractable signing key = master key to tenants. https://www.techtarget.com/cybersecurity/news/366577765/Cyber-Safety-Review-Board-slams-Microsoft-security-failures ; https://www.bleepingcomputer.com/news/security/microsoft-still-unsure-how-hackers-stole-msa-key-in-2023-exchange-attack
- Okta support system breach (Sep-Oct 2023): 134 customers' files exposed; HAR files with session tokens used to hijack sessions at 5 customers (1Password, BeyondTrust, Cloudflare). Root: service account credentials saved in personal Google profile. https://www.bleepingcomputer.com/news/security/okta-breach-134-customers-exposed-in-october-support-system-hack/
- Snowflake (2024): ~165 customers hit via stolen credentials (infostealers, some dating to 2020), no MFA, no rotation, no network allow-list (Mandiant UNC5537). https://thehackernews.com/2024/06/snowflake-breach-exposes-165-customers.html
- Bybit (Feb 2025, ~$1.5B): Lazarus compromised a Safe{Wallet} developer machine, injected JS into Safe UI so multisig signers approved a malicious tx they could not see. Lesson: quorum is not enough if each approver sees a spoofed intent; need approver-side verification of what is actually signed. https://www.bleepingcomputer.com/news/security/lazarus-hacked-bybit-via-a-breached-safe-wallet-developer-machine/ ; https://nccgroup.com/sg/research-blog/in-depth-technical-analysis-of-the-bybit-hack
- Relevance to TideCloak: keys never assembled in one place (threshold), admin actions need quorum -> addresses Storm-0558 / insider / compromised-admin class. Bybit shows approval-UI integrity still needs care (honest caveat).

## 5. Market solutions and the gap
- Detection / runtime guardrails: Lakera (acquired by Check Point, ~$300M, announced Sep 2025; multilingual claims, >98% detection claimed by vendor) https://www.csoonline.com/article/4058653/check-point-acquires-lakera-to-build-a-unified-ai-security-stack.html ; Prisma AIRS (Palo Alto, closed Jul 2025 - Protect AI); HiddenLayer independent. Prompt Security: acquired by SentinelOne [UNVERIFIED, from memory, not confirmed in searches]. Cloudflare AI Gateway/Firewall for AI [not researched].
- Agent identity: Microsoft Entra Agent ID (unique identity per agent in Foundry/Copilot Studio; OAuth2, MCP, A2A; third-party via SDK/federation) https://learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id ; Okta Cross App Access + Auth0 Token Vault w/ downscoping (Oktane Sep 2025; CAA early access Jan 2026) https://www.okta.com/en-se/newsroom/press-releases/okta-introduces-cross-app-access-to-help-secure-ai-agents-in-the/ ; Aembit blended identity (user + workload evaluated together) https://aembit.io/vendor/aembit-vs-microsoft-entra-id/ ; Astrix (NHI discovery) and Permit.io (fine-grained authz) [not researched, UNVERIFIED].
- Gap (analysis, not sourced): (1) classifiers are probabilistic; EchoLeak bypassed Microsoft's own. (2) Identity vendors are themselves centralized, single-admin/single-signing-key trust roots (Okta 2023, Storm-0558). (3) Tokens/secrets are still bearer and held by the agent or a vault admin; no cryptographic binding between human intent, specific action, and execution. (4) Approval is single-click, fatigue-prone, with no quorum for high-risk actions. (5) Data confidentiality ("identity-bound encryption") rarely enforced at the data layer, so a hijacked agent with broad read access sees plaintext.

## 6. Sector pain
- Finance/payments: Agentic commerce protocols (Stripe/OpenAI ACP, Google AP2) in production; once an agent is compromised its transactions look normal; Visa PERC reported >450% rise in dark-web "AI agent" posts H1 2026 [UNVERIFIED secondary]. Need scoped, revocable, spend-capped credentials. https://workos.com/blog/how-to-secure-agentic-commerce ; https://hackernoon.com/designing-guardrails-for-ai-agents-that-spend-real-money
